# Endpoints

Every route of the backend: its body, what it returns and what it refuses. Moved out of `CLAUDE.md` (which keeps an index by resource) when that file passed its size budget. **Update this list when endpoints change**; the sections under "Coding conventions" in `CLAUDE.md` have the rules behind each entry, and a section named in an entry ("see Properties") is one of them.

- `GET /status`
- `POST /v1/auth/login` — email (matched without regard to case) and password; returns `{access_token, token_type, expires_in, user}`, or 401 `Invalid email or password` (a deleted user gets the same)
- `GET /v1/auth/me` — the user the bearer token belongs to, with `has_signature` and `signature_set_at`; 401 `Not authenticated`, `Token expired` or `Invalid token`
- `POST /v1/auth/demo` — public; makes a throwaway demo user on `DEMO01` and returns what login returns; 503 when `DEMO01` is missing or 200 demo users already exist
- `POST /v1/auth/logout` — 204 always; stateless, the client drops its token. A demo user signing out is deleted with everything they made

Every route below needs a bearer token (401 without a valid one); see "Sign-in" under the conventions.

- `POST` or `GET /v1/admin/cleanup-demos` — deletes demo users older than 24 hours; returns `{purged_count}`. For a signed-in admin, or the scheduler sending `CRON_SECRET` as its bearer token; 403 for anyone else signed in
**Admin users, projects and pay items.** Admin only (403 `Admin access required`), responses under `data`. The routes check values themselves, so one that doesn't fit is a 400, not FastAPI's 422 (the rules: "Sign-in" and "Admin pay-item routes" under the conventions).
- `GET /v1/admin/users?include_deleted=` — every user, demo users included, by last name, first name and email, each as `/v1/auth/me` returns one (`uuid`, `email`, `first_name`, `last_name`, `role`, `is_demo`, `has_signature`, `signature_set_at`) plus `deleted_at` and `deleted_by`; deleted users only with `include_deleted=true`
- `POST /v1/admin/users` — body `{email, first_name, last_name?, password, is_admin?}`; 201. 400 for a blank or malformed email, a blank or over-long name, or a password under 6 characters or over 72 bytes; 409 `{detail, existing_user_uuid}` when the email is taken, whatever its capitals
- `PATCH /v1/admin/users/{user_id}` — any of `{first_name, last_name, email, is_admin, is_demo}`, trimmed (`role` comes back `admin` or null). 400 when nothing is sent (a null counts as not sent), a name is blank or over 100 characters, the email is blank or malformed, `is_admin: false` from an admin for themselves (`You cannot revoke your own admin role.`) or `is_demo: true` for a real user (`Cannot change a real user to a demo user.`); 404; 409 as on create
- `POST /v1/admin/users/{user_id}/delete` — the soft delete (`deleted_at`, `deleted_by`; nothing else of theirs changes). 400 `You cannot delete your own account.`, 404 `User is already deleted` · `POST /v1/admin/users/{user_id}/undelete` — 404 `User is not deleted`, 409 `{detail, existing_user_uuid}` when another user now has their email
- `DELETE /v1/admin/users/{user_id}/permanent` — a soft-deleted user, for good, 204. 404 `User must be soft-deleted first`; 409 `{detail, references: {idrs, project_users, audit, field_edits, attachments, properties, task_orders, task_order_properties, pirs, flags, pir_pages, non_assessable_areas, features, segments, idr_flag_attributions}}` when anything still names them
- `POST /v1/admin/users/{user_id}/password` — body `{new_password}`, any user's, the admin's own included; 400 for a password under 6 characters or over 72 bytes
- `GET /v1/admin/projects` — every project, by id, as `GET /v1/projects/{project_id}` returns one (`project_id`, `project_name`, `project_description`, `registration_code`, `borough`, `status`, `cost_per_sf_4in`, `cost_per_sf_7in`) · `POST` — body `{project_id, project_name, project_description, borough, registration_code?}`; 201. 400 for a blank or over-long value, or a `project_id` with anything but letters, digits, hyphens and underscores; 409 `{detail, existing_project_id}`
- `PATCH /v1/admin/projects/{project_id}/assessment-rates` — body `{cost_per_sf_4in?, cost_per_sf_7in?}`, the DOT's rates per square foot (one left out keeps its value, a null clears it). 400 when nothing is sent or a rate is negative, a million or more, or past 4 decimal places; 422 for one that isn't a number; 404
- `GET /v1/admin/projects/{project_id}/pay-items` — by budget code then ref: `[{pay_item_uuid, pay_item_ref, description, unit, quantity, unit_price, budget_code, spec_section}]`. Every pay-item route is 404 for an unknown project
- `POST /v1/admin/projects/{project_id}/pay-items` — body `{pay_item_ref, description, unit, quantity, unit_price, budget_code, spec_section?}`; 201. 400 for a blank or over-long value, an unknown unit, or a negative or over-precise amount; 409 `{detail, existing_pay_item_uuid}` when the project has that ref under that budget code · `PATCH /v1/admin/projects/{project_id}/pay-items/{pay_item_uuid}` (any of the seven; a null clears `spec_section` only; 404 for an item the project doesn't have; 409 as on create) · `DELETE /v1/admin/projects/{project_id}/pay-items/{pay_item_uuid}` (204) · `DELETE /v1/admin/projects/{project_id}/pay-items` (every one; `{deleted_count}`)
- `POST /v1/admin/projects/{project_id}/pay-items/import/preview` — a CSV as the multipart field `file`; writes nothing; `{parsed_rows, new_count, overwrite_count, error_count, ignored_columns, new, overwrites, errors}`. 400 for a file that isn't UTF-8, isn't a CSV, has no header row or lacks a required column; 413 over 2 MB
- `POST /v1/admin/projects/{project_id}/pay-items/import/commit` — the same upload, read and checked again, then written in one statement; `{inserted, updated}`. 400 `{detail, error_count, errors}` when any row has an error (nothing is written), 400 for a file with no rows, and the preview's 400s and 413
- `POST /v1/signatures/upload-request` — body `{content_type: "image/png"}`; returns `{upload_url, storage_path, expires_in}`, a signed URL to PUT the signed-in user's signature PNG to (it replaces their current one); 403 for a demo user
- `POST /v1/signatures/confirm` — body `{signature_type: "drawn" | "uploaded"}`; records the uploaded file as the user's signature and returns the user; 400 `Upload the signature before confirming` when no file is there; 403 for a demo user
- `GET /v1/users/` — every user who isn't deleted; 403 for a demo user
- `POST /v1/users/me/password` — body `{current_password, new_password}`; the signed-in user changes their own password; returns `{status, message, data: null}`. 400 for a blank current password, `Current password is incorrect`, a new one under 6 characters or over 72 bytes, or `New password must differ from current`; 403 for a demo user
- `GET /v1/projects/` — the signed-in user's projects (through `project_users`), each once, with `roles` (the project roles they hold on it) and `user_role` (the label)
- `GET /v1/projects/{project_id}`
- `GET /v1/projects/{project_id}/roles` — admin only: who holds which role on the project, one entry per user and role (demo users left out)
- `POST /v1/projects/{project_id}/roles` — admin only: body `{user_uuid, role: "inspector" | "oe" | "re", action: "grant" | "revoke"}`; returns the project's roles as they now stand. Safe to repeat: granting a role already held, or revoking one not held, is a 200 that changes nothing. 404 for an unknown project or user, 400 for a demo user
- `GET /v1/projects/{project_id}/quantities?from=&to=&pay_item=&budget_code=&discipline=&inspector_uuid=&cumulative=` — the pay-item quantities of the project's approved IDRs and what they come to against its contract items: `{range, rows, totals_by_unit, row_count, truncated, pay_items, totals_by_budget_code, project_total, unbudgeted_total}` under `data` (filters and figures: "Quantities"). For a user on the project, or an admin: 403 otherwise, 404 for an unknown project, 400 for a bad date, `from` after `to`, or an unknown discipline
**Sites and PIR drawings.** The routes from properties to the Smart PIR import share these rules; each entry gives only what differs (the sections under the conventions have the rest):
- Every response is under `data`. Reads take a user on the project (any role) or an admin: 403 `Project access required` otherwise (a demo user gets 404 for another project's), 404 for an unknown row.
- Writes take the same but never a demo user: 403 `Demo mode: properties are read-only`, `Demo mode: task orders are read-only`, `Demo mode: flags are read-only` (flags and areas) or `Demo mode: PIRs are read-only` (PIRs, pages, features, segments, title blocks, the import). `created_by`, `added_by` and `digitized_by` are the signed-in user.
- Under anything soft-deleted, a user who isn't an admin gets 400 `Property is deleted`, `Task order is deleted`, `PIR is deleted`, `Page is deleted`, `Flag is deleted`, `Non-assessable area is deleted`, `Feature is deleted` or `Segment is deleted`; nobody adds to a replaced page (400 `Page is deleted` for everyone).
- PATCH lays the body over the stored row and checks the whole as create does (a 422 in FastAPI's shape); 400 when nothing is sent; a null counts as not sent unless the entry says it clears. A `pay_item_id` must be a contract item of the project: 400 `Pay item belongs to a different project`.
- `DELETE` is a soft delete: 204, and again is a 204 that changes nothing. `POST .../admin/soft-delete` (admin only) is a 200 that changes nothing on a row already deleted; `POST .../admin/undelete` (admin only) is 404 (`Property is not deleted`, `Task order is not deleted`, `PIR is not deleted`, `Flag is not deleted`) for a live one, and 409 `{detail, existing_<row>_id}` when its unique slot has been taken since.

- `GET /v1/projects/{project_id}/assessment-summary.xlsx?from=&to=` — the project's Assessment Summary, an .xlsx (see `CLAUDE.md`, "Assessment Summary"): a tab per month of construction (`YYYY-MM`), a row per property, a totals row; one `No activity` tab when there is nothing (200). `from` and `to` are `YYYY-MM`, inclusive, either left out: 400 `from must be YYYY-MM` / `to must be YYYY-MM`, 400 `from after to`. For a user on the project, or an admin: 403 otherwise, 404 for an unknown project; a demo user reads their own project's
- `GET /v1/projects/{project_id}/properties?include_deleted=&kind=` — by address (a ped ramp's intersection), each with `pir_status` (`none`, `dot_signed`, `as_built_signed`), `status` (`{state: none | task_ordered | constructed_on, date}`) and `task_order_no` (see "Properties"). `include_deleted=true` adds the soft-deleted ones for an admin and is ignored for anyone else; `kind` (`sidewalk` or `ped_ramp`, else 422) keeps one kind
- `POST /v1/projects/{project_id}/properties` — body `{kind?, notes?}` and a sidewalk's `{boro, block, lot, address, property_type, violation_no?}` (no `kind` is a sidewalk) or a ped ramp's `{boro, intersection_street_1, intersection_street_2, quadrant, facing_street, ramp_type}`; 201. 400 for a blank or over-long value; 422 for an unknown value, a block or lot that isn't a tax map number, a field the kind needs left out or one of the other kind; 409 `{detail: "A site at Queens Block 123 Lot 45 already exists in this project.", existing_property_id}` for a live sidewalk of the project at the borough, block and lot
- `GET /v1/properties/{property_id}` (deleted or not) · `PATCH /v1/properties/{property_id}` (its kind's fields and `notes`; a null clears `notes` and `violation_no`; 400 `Property kind cannot be changed. Delete and recreate.`; 409 as on create) · `POST /v1/properties/{property_id}/admin/soft-delete` · `POST /v1/properties/{property_id}/admin/undelete`
- `GET /v1/projects/{project_id}/task-orders?include_deleted=` — by number, each with `property_count` (its live bundled properties) instead of them (see "Task orders"); `include_deleted` as for properties
- `POST /v1/projects/{project_id}/task-orders` — body `{task_order_number, issued_date?, estimate_notes?}`; returns it with `properties: []`, 201. 400 for a blank or over-long value, 422 for a malformed date, 409 `{detail, existing_task_order_id}` when a live task order of the project has the number
- `GET /v1/task-orders/{task_order_id}` (deleted or not, with `properties`: its live bundled ones, by address, each as `/v1/properties/{id}` returns one) · `PATCH /v1/task-orders/{task_order_id}` (any of the three; a null date or notes clears; 409 as on create) · `POST /v1/task-orders/{task_order_id}/admin/soft-delete` (keeps the bundle) · `POST /v1/task-orders/{task_order_id}/admin/undelete` (the bundle as it was)
- `POST /v1/task-orders/{task_order_id}/properties/{property_id}` — bundles it, `added_by` the signed-in user; returns the task order with its properties, 201. 400 `Property belongs to a different project`, or a deleted task order or property; 409 `Property is already in this task order`
- `DELETE /v1/task-orders/{task_order_id}/properties/{property_id}` — unbundles it, 204, whatever the property's state; only an admin unbundles from a soft-deleted task order. 404 `Property is not in this task order`
- `GET /v1/properties/{property_id}/construction-report?idr_id=` — the property's Construction Report, a PDF (see "Construction Report"); 404 when no approved IDR (or not the given one) claimed a flag on it; 422 for a sketch on more than one page, too large for one sheet or on a page without a scale
- `GET /v1/projects/{project_id}/progress-rollup?task_order_id=&property_id=&include_empty=` — the project's flags per pay item a flag can fill (those its flags in scope are on; `include_empty=true` lists all): `{scope, pay_items: [{pay_item_id, item_no, budget_code, description, unit, unit_price, approved, in_flight, unclaimed, live_total, approved_pct}], unmapped_flag_count, unmapped_by_property, overall: {approved_value, live_total_value, approved_pct}}`, each state `{quantity, flag_count, value}` (see "Progress"). The filters narrow to a live task order's properties and to one live property (404 for one that isn't; how they combine: "Progress")
- `GET /v1/task-orders/{task_order_id}/progress-rollup?include_empty=` — the same over the task order's live bundled properties (a soft-deleted task order's too), plus `properties` (each one's own rollup, in the task order's order), `site_count` and `sites_started`
- `GET /v1/properties/{property_id}/pir` — the live PIR (see "PIRs"); 404 `No PIR for this property` · `GET /v1/properties/{property_id}/pirs?include_deleted=` — its PIRs, most recently digitized first: the live one, and the soft-deleted ones for an admin who sends `include_deleted=true`
- `POST /v1/properties/{property_id}/pir` — body `{inspector_initials, inspector_sign_date}`; `digitized_at` now; 201. 400 for blank or over-long initials or a soft-deleted property (for everyone), 422 for a malformed date, 409 `{detail, existing_pir_id}` when the property has a live PIR
- `GET /v1/pirs/{pir_id}` (deleted or not) · `PATCH /v1/pirs/{pir_id}` (`inspector_initials`, `inspector_sign_date`, `north_bearing`: `N` `NE` `E` `SE` `S` `SW` `W` `NW`, else 422; a null clears the bearing) · `POST /v1/pirs/{pir_id}/admin/soft-delete` (frees the property for a new PIR) · `POST /v1/pirs/{pir_id}/admin/undelete` (409 when the property has another live PIR)
- `POST /v1/pirs/{pir_id}/image/upload-request` — body `{mime, filename?, size_bytes?}` (`application/pdf`, `image/png`, `image/jpeg`); returns `{upload_url, staging_path, expires_at}`, a signed URL to PUT the file to at `staging/{pir_id}/{uuid}.{ext}` (see "PIR pages"). 400 `Unsupported file type` or `mime is required`; 413 `File too large` for a `size_bytes` over the limit; 502 when Storage can't sign
- `POST /v1/pirs/{pir_id}/image/complete` — body `{staging_path, scale_px_per_ft?}`; renders every page of a PDF (or the one PNG or JPEG) to PNG, stores them and replaces the PIR's pages with them, its live drawings on the old pages soft-deleted in the same statement. Returns the PIR with `pages` (each with a signed `image_url`). 400 for a missing path, a scale that isn't above 0, a path that isn't one of the PIR's uploads or has no file, a file that isn't a PDF, PNG or JPEG by its bytes or can't be read, or one over a cap (`The PDF has 16 pages; a PIR can have at most 15 (PIR_UPLOAD_MAX_PAGES)`, `Page 2 at 150 DPI is 39.1 megapixels; a page can be at most 25 (PIR_UPLOAD_MAX_MEGAPIXELS_PER_PAGE)`); 413 `File too large`; 502 when Storage fails
- `GET /v1/pirs/{pir_id}/pages` — its live pages in order, each `{pir_page_id, pir_id, page_number, image_url, image_url_expires_at, image_mime, width_px, height_px, scale_px_per_ft, rotation_deg, created_at, updated_at, deleted_at, deleted_by}` · `DELETE /v1/pirs/{pir_id}/pages` — soft-deletes the live pages and their live flags (with their areas), features and segments in one statement, the files kept; 204, a PIR without pages included
- `PATCH /v1/pir-pages/{pir_page_id}/scale` — body `{scale_px_per_ft}` (above 0, else 400); that page only, its live segments' lengths worked out again in the same statement; 404 `Page not found` · `PATCH /v1/pir-pages/{pir_page_id}/rotation` — body `{rotation_deg}` (0, 90, 180 or 270, else 422)
- **DEPRECATED (R1e), still served, and not called by the frontend:** `GET /v1/pirs/{pir_id}/image`, `PATCH /v1/pirs/{pir_id}/image` (`{scale}`) and `DELETE /v1/pirs/{pir_id}/image` (page 1's link and scale, page 1's scale, DELETE `.../pages`; 404 `No image for this PIR` without pages) and `POST /v1/pirs/{pir_id}/flags` (onto page 1; 400 `Upload the PIR image first`). The upload pair still takes R1d's bodies (`{content_type}`, `{upload_path, scale}`) and returns R1d's keys too (`upload_path`, `expires_in`; `signed_url`, `expires_at`). (see "Known rough edges")
- `GET /v1/pirs/{pir_id}/flags?include_deleted=` — across its live pages, by `display_order` then creation (see "Flags"); an admin's `include_deleted=true` gives every flag it has had · `GET /v1/pir-pages/{pir_page_id}/flags` — the page's live flags; 404 `Page not found`
- `POST /v1/pir-pages/{pir_page_id}/flags` — body as "Flags" lists it; its `computed_quantity` the area of its shape; 201. 422 for dimensions that don't fit the shape, a broken rule or a pay item in a unit a flag can't measure
- `GET /v1/flags/{flag_id}` (deleted or not) · `PATCH /v1/flags/{flag_id}` (the area computed again; 422 for a new `shape` without its `dimensions`; a null clears what "Flags" lists) · `DELETE /v1/flags/{flag_id}` (an admin can bring it back) · `POST /v1/flags/{flag_id}/admin/soft-delete` · `POST /v1/flags/{flag_id}/admin/undelete` (its areas deleted with it come back too; 400 `This flag has no page; draw it again` or `Its page was replaced`)
- `GET /v1/flags/{flag_id}/non-assessable-areas` — its live areas, by `display_order` (see "Non-assessable areas, features and segments") · `POST /v1/flags/{flag_id}/non-assessable-areas` — body `{display_order, shape, dimensions, sketch_x, sketch_y, rotation?, reason}`; 201. 400 `Flag is deleted` or `Page is deleted` for everyone; 409 when a live area of the flag has the `display_order`; 422 for dimensions that don't fit the shape
- `GET /v1/non-assessable-areas/{non_assessable_area_id}`, `PATCH` (409 as on create) and `DELETE` on the same path
- `GET /v1/pir-pages/{pir_page_id}/features` and `GET /v1/pirs/{pir_id}/features` — live, by page, in drawing order · `POST /v1/pir-pages/{pir_page_id}/features` — body `{feature_type, area_impact?, sketch_x, sketch_y, rotation?, shape?, dimensions?, label?, pay_item_id?, flag_id?, reported_quantity?}`; 201. 400 `Flag is not a live flag on this page`; 422 for a broken rule · `GET /v1/features/{feature_id}`, `PATCH` (a null clears `shape`, `dimensions`, `label`, `pay_item_id`, `flag_id` or `reported_quantity`) and `DELETE` on the same path
- `GET /v1/pir-pages/{pir_page_id}/segments` and `GET /v1/pirs/{pir_id}/segments` · `POST /v1/pir-pages/{pir_page_id}/segments` — body `{segment_type, points: [{x, y}, ...] (two or more), pay_item_id?, note?}`; `length_ft` from the points and the page's scale (null while it has none); 201 · `GET /v1/segments/{segment_id}`, `PATCH` (the length worked out again; a null clears `pay_item_id` or `note`) and `DELETE` on the same path
- `GET /v1/pir-pages/{pir_page_id}/annotations` — the page's title block, or `data: null` · `PUT /v1/pir-pages/{pir_page_id}/annotations` — the title block, `date_notice_issued`, `date_excavated` and `date_constructed` included: a field sent is written (a null clears it), one left out keeps its value; 422 for a value that doesn't fit
- `POST /v1/pirs/{pir_id}/import` — a Smart PIR import file (see "Smart PIR import"), each item that fails its check dropped; returns `{inserted, dropped, dropped_items, pages_updated}`. 400 `The file's pir_id is not this PIR`; 422 for a file that isn't a Smart PIR import

- `POST /v1/idrs/` — create a draft IDR for the signed-in user, its reporter, with an optional `task_order_id` (its default flag scope; 400 for one that isn't a live task order of the project) (409 with `existing_idr_id` if one exists for that reporter, project and date)
- `GET /v1/idrs/?project_id=&status=&reporter_uuid=&idr_number=&work_date=&from=&to=&discipline=` — the archive: IDRs with `report_count`, `has_general`, `disciplines` and the names of the inspector and reviewers (filters and their 400s: "The archive"). Deleted IDRs and other people's drafts are left out; an admin can add `include_deleted=true` and `include_all_drafts=true` (400 for anyone else who sends either as true)
- `GET /v1/idrs/{idr_id}` — IDR plus all its reports, in page order, and `field_edits`: every edit reviewers made on it, oldest first, each with `editor_name` and `editor_initials`
- `PUT /v1/idrs/{idr_id}/header` — partial update of the shared header fields and `task_order_id` on a draft (null clears; 400 for a task order that isn't a live one of its project)
- `POST /v1/idrs/{idr_id}/reports` — add a report (typed by `ReportType`; addendums may name a parent)
- `PUT /v1/idrs/{idr_id}/reports/{report_id}` — replace a report's `report_data` (any JSON object); 400 when its `payItems` hold an item (item number and budget code) the IDR's flags fill
- `DELETE /v1/idrs/{idr_id}/reports/{report_id}` — remove a report (its addendums cascade)
- `POST /v1/idrs/{idr_id}/submit` — submit a draft, signed by the signed-in user (locks it, numbers pages, sets `total_pages`, stamps `inspector_signature_path` and `inspector_signed_at`, clears any return); 400 `Signature required before submitting` when they have no signature, 502 when it can't be copied, 403 `Demo mode: submit is disabled` for a demo user, 403 `Role required: inspector` for a user who isn't an inspector on the project
- `GET /v1/idrs/queue?status=submitted|stage1_review|stage2_review` — one review queue, oldest submission first, on the projects where the signed-in user works it (OE or RE; RE only for `stage2_review`; an admin, every project), rows as the IDR list's
- `POST /v1/idrs/{idr_id}/accept-stage1` — an OE or RE takes a submitted IDR: → `stage1_review`, the caller its Stage 1 reviewer (the accepted times: "Pay-item attestation"). Body `{idr_number}`, needed the first time (400 without it); a number once given is kept. 409 with `existing_idr_id` when the number is in use on the project
- `POST /v1/idrs/{idr_id}/approve-stage1` — the Stage 1 reviewer only (403 for another OE or RE): → `stage2_review`, once they have attested to every pay item at this stage, else 400 `{detail, untouched: [{pay_item_id, report_id, item_no, budget_code}]}`
- `POST /v1/idrs/{idr_id}/accept-stage2` — an RE becomes `re_reviewer_uuid`; the status stays `stage2_review`, and the last to accept wins
- `POST /v1/idrs/{idr_id}/approve-stage2` — the RE reviewer only, signed: → `approved`, `re_signature_path` and `re_signed_at` stamped, its attributed flags claimed and its quantities written (see "Quantities", "IDR flags"); the response carries `flags_claimed` and `flags_dropped` (claimed first by another IDR; the message says so). The same 400 with `untouched` (flag lines need none); 400 `Signature required before approving`; 502 when the signature can't be copied
- `POST /v1/idrs/{idr_id}/return` — the current stage's reviewer: body `{to: "inspector" | "oe", comment}` (400 for a blank comment); to `draft`, or from Stage 2 to `stage1_review`, with `return_reason` and `returned_from` (what a return clears: "Review" and "Pay-item attestation")
- `PATCH /v1/idrs/{idr_id}/field` — the current stage's reviewer (or an admin) edits one field of an IDR in review: body `{report_id, field_path, new_value}` (`report_id` left out for `header.<column>`); returns the IDR with its reports and `field_edits` (see "Reviewer edits"). 400 when the IDR isn't in review, the path isn't a field of the report, the value doesn't fit, or nothing changes; 403 for anyone but that reviewer; 409 if the field changed meanwhile
- `POST /v1/idrs/{idr_id}/pay-items/{pay_item_id}/revise` — same caller: body `{revised_quantity}`, the item found by its id in whichever report holds it (404 when none does) · `POST /v1/idrs/{idr_id}/pay-items/{pay_item_id}/approve` — no body: logs their approval of the item as it stands; again at this stage is a 200 that logs nothing · `POST /v1/idrs/{idr_id}/pay-items/add` — body `{report_id, item_no, budget_code, quantity, unit, description}`, appended to that General, SWCB or AC
- `POST /v1/idrs/{idr_id}/reports/{report_id}/trucks/add` — same caller: a truck with any of the keys the form saves (`truckOrTicketNo`, `slump`, `loadSizeCy`, `endBatch`, `mixingRevs`, `startDischTime`, `endDischTime`, `airContent`, `concTemp`, `cylinderNumbers`, `inspectionSticker`), appended to that CONC_MIX. 400 for another report type, or a truck with neither a truck or ticket number nor a slump
- `POST /v1/idrs/{idr_id}/admin/unlock` — admin only: an approved IDR (or one in `stage2_review`) back to `stage2_review`, the RE's signature, reviewer and acceptance cleared, so an RE must accept and approve again; the number stays, its quantity rows go and its claims are released (`flags_released`). 400 for a draft, submitted, Stage 1 or deleted IDR
- `POST /v1/idrs/{idr_id}/admin/delete` — admin only: the soft delete, at any status (see "Review"); its quantity rows go and its claims are released (`flags_released`, recorded for an un-delete). Again is a 200 that changes nothing
- `GET /v1/idrs/{idr_id}/construction-reports` — an approved IDR's Construction Reports, a ZIP of one PDF per property it claimed flags on; a user with a role on its project, or an admin. 404 `IDR is not approved` or `This IDR claimed no flags`; 422 naming the property whose sketch won't fit
- `GET /v1/idrs/{idr_id}/attributed-flags` — the flags an IDR covers and their rollup per pay item (see "IDR flags"); for anyone who can read the IDR
- `POST /v1/idrs/{idr_id}/attributed-flags/{flag_id}/exclude` and `.../include` — leave a flag out of an IDR, or put one in; return the same as the GET. Its inspector on a draft, the stage's reviewer in review, an admin either way; 403 for anyone else and a demo user (`Demo mode: IDR flags are read-only`); 409 for an approved, deleted or submitted (not yet accepted) IDR, or a flag another IDR claimed (`Flag is claimed by IDR 003`); 404 for a flag not of its project; 400 `Flag is deleted` on include
- `POST /v1/idrs/{idr_id}/admin/undelete` — admin only: back with the status it had when deleted (a draft when that isn't on record, and the message says so); one that comes back approved claims back the flags its delete released (`flags_claimed`) and gets its quantity rows back. 404 `IDR is not deleted`; 409 with `existing_idr_id` when another IDR has taken its day or its number, or claimed one of those flags since
- `DELETE /v1/idrs/{idr_id}/admin/permanent` — admin only: a soft-deleted IDR for good, with everything under it and its files; 204, no undo. 404 `IDR must be soft-deleted first`
- `POST /v1/idrs/{idr_id}/reports/{report_id}/attachments/upload-request` — start a two-step upload: records a pending attachment (name, description, file details; `uploaded_by` is the signed-in user) and returns a signed Storage upload URL plus the headers to send; draft only, not on an auto-General
- `POST /v1/idrs/{idr_id}/reports/{report_id}/attachments/upload-complete` — mark a pending attachment uploaded once its file is in Storage (`attachment_id` in the body); draft only
- `PUT /v1/idrs/{idr_id}/reports/{report_id}/attachments/{attachment_id}` — replace an attachment's name and description; draft only
- `GET /v1/idrs/{idr_id}/reports/{report_id}/attachments` — list a report's uploaded attachments (pending ones left out)
- `GET /v1/idrs/{idr_id}/reports/{report_id}/attachments/{attachment_id}/download-url` — short-lived signed URL; 404 while pending
- `DELETE /v1/idrs/{idr_id}/reports/{report_id}/attachments/{attachment_id}` — remove an attachment, pending or uploaded (Storage file, then record); draft only
- `GET /v1/idrs/{idr_id}/export` — an IDR as an .xlsx on the DDC report-forms template (General, SWCB, AC, Conc Mix and Conc Cyl pages) (a draft's pages are marked "DRAFT - Not for Submission"), stored in the `idr-exports` bucket; returns `{download_url, filename}`, the URL valid 10 minutes
- `GET /v1/contract_items/?project_id=` — a project's contract items for the pay-item picker, each with its `item_no`, `description`, `spec_section` (null when it has none) and `pay_unit`, by item number then budget code; `[]` when none
